Apply the spec-driven-development skill. Write a specification before any code.

The specification must cover all six areas:

### 1. Goal
One sentence: "This feature lets [user type] do [action] so that [outcome]."

### 2. Users
Who uses this? What are their goals and constraints?

### 3. Functional Requirements
What must the system do? Use MUST / SHOULD / MAY.

### 4. Non-Functional Requirements
Performance targets, security requirements, accessibility level, scalability.

### 5. Assumptions
What are you assuming is true? List them explicitly so they can be challenged.

### 6. Out of Scope
What are we explicitly NOT building in this iteration?

---

After writing the spec, wait for approval before proceeding to planning.

**Do not write code until the spec is approved.**
